What this measures

Ingest → serve latency = server_ts − event.timestamp — the time from Spark's rate source emitting a row to the FastAPI backend returning it from Lakebase. Each step in the path contributes to the number you see in the KPI tile:

①  Spark rate source emits row              event.timestamp = T₀
   src/notebooks/stream.py
         │
         ▼
②  Native `format("postgresql")` sink
   buffers up to `batchinterval` (100 ms)
   or `batchsize` (1000 rows), workspace-
   managed JDBC connection
   src/notebooks/stream.py
         │
         ▼
③  Lakebase commits an upsert
   into the `events` table
   (INSERT … ON CONFLICT via PRIMARY KEY)
         │
         ▼
④  FastAPI's GET /api/events/latest
   runs `SELECT … FROM events`              server_ts = T₁
   src/app/main.py
         │
         ▼
⑤  JSON response leaves the API
   src/app/main.py

         Ingest → serve = T₁ − T₀

The browser-side leg (HTTPS round-trip + JS parse) sits after step ⑤ and is intentionally excluded — this number is the latency inside Databricks.
